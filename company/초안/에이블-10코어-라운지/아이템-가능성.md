# 에이블 라운지 — 캐릭터 꾸밈 아이템(모자·가방·안경·신발) 가능성 조사

- 날짜: 2026-11-06 · 개발팀 · 대상: 에이블 라운지 (able-lounge.pages.dev)
- 회장님 지시 원문 (11/6): "선물을 아이템으로 주면 좋겠다는 얘기를 하거든 그냥 진짜 선물 말고 아이템 예를 들면 모자 가방 안경 신발 이런 여기 캐릭터에 쓸 수 있는 거 있잖아 혹시 그게 가능한지 한번 알아볼래"
- 이 문서는 판단만 담았다. 코드는 아직 만들지 않았다.

## 한 줄 결론
**가능하다.** 캐릭터가 동그라미·막대 같은 단순한 도형을 조립해 만든 것이라, 모자·안경·가방·신발도 같은 방식으로 붙이면 된다. 이미 헤드폰과 두피 관리 모자를 머리에 씌우고 컵과 물병을 손에 쥐여 주고 있어서, 같은 방식이 잘 돌아가는 것도 확인돼 있다.
다른 사람 화면에 보이게 하는 데 드는 서버 사용량은 아주 작아서 무료 요금 안에 넉넉히 들어간다. 다만 **서버 설정(SQL)이 하나 필요하다** — 크롬 Claude 지시문을 따로 써야 한다.

---

## 1. 지금 캐릭터는 어떻게 그려지나
- 3D 모델 파일(사람 모양 파일)을 쓰지 않는다. 화면을 그리는 도구(three.js)로 **도형을 조립**한다:
  몸통 = 알약 모양 1개, 머리 = 공 1개, 머리카락 = 반구(여자는 단발, 남자는 짧은 머리), 눈·볼 = 작은 공, 팔·다리 = 작은 알약 모양, 셔츠 깃, 이름표.
- 몸은 "골반 → 몸통 → 머리 / 팔 / 다리" 순서로 이어져 있어서, **머리에 붙인 물건은 머리를 따라 움직이고 다리에 붙인 물건은 다리를 따라 움직인다** (걷기·앉기·자전거 타기 자세도 그대로 따라감).
- 이미 물건을 붙여 쓰고 있다: 강의 들을 때 헤드폰(머리), 두피 관리 모자(머리), 책(몸통 앞), 얼굴 미용 기기·컵·영양제·청소기·물병(오른손). 평소에는 숨겨 두었다가 그 자리에 앉을 때만 보인다.
- 옷 색은 이름으로 정해진다 (같은 이름이면 늘 같은 색). 지금은 꾸밀 수 있는 것이 여자/남자 고르기뿐이다.

## 2. 아이템을 얹을 수 있나 — 부위별
| 아이템 | 붙일 곳 | 난이도 | 메모 |
|---|---|---|---|
| 모자 (야구모자·밀짚모자·비니) | 머리 | 쉬움 | 머리카락 위에 얹으면 된다. 두피 관리 모자·헤드폰을 쓸 때는 잠깐 숨김 (겹침 방지) |
| 안경·선글라스 | 머리 (눈 앞) | 쉬움 | 테 2개 + 다리 막대. 얼굴 미용 자리에서는 숨길지 정해야 함 |
| 가방 (크로스백·백팩) | 몸통 | 쉬움~보통 | 앉을 때 의자와 겹치지 않게 등 쪽보다 옆구리 쪽이 안전. 자전거·요가 자세 확인 필요 |
| 신발 (운동화 색) | 다리 끝 | 보통 | 지금은 발이 따로 없고 다리 끝이 둥글다. 다리 끝에 작은 신발 모양을 붙이고, 앉기·요가 자세에서 바닥을 뚫지 않는지 확인 필요 |
| (덤) 목도리·배지·옷 색 | 몸통 | 쉬움 | 같은 방식으로 가능 |

- 휴대폰 부담: 아이템 1개 = 도형 2~5개. 20명이 모두 4개씩 써도 그리기 양이 조금 늘 뿐이다. 다만 "그리기 횟수"가 늘어나므로, 만들 때 오래된 휴대폰 기준으로 속도를 다시 잰다 (라운지는 느려지면 화면 선명도를 저절로 낮추는 장치가 이미 있음).
- 글자·로고는 넣지 않는다 (지금 라운지 원칙 그대로: 회사·제품 이름 글자 없음).

## 3. 다른 사람 화면에도 보이게 하려면 — 실시간 메시지·서버 저장
지금 라운지는 내 위치를 이렇게 보낸다: 들어올 때 한 번 + 멈췄을 때 마지막 자리 한 번(30초에 4번까지), 걸을 때는 짧은 '이동' 메시지. 보내는 내용은 이름·여자/남자·위치·앉은 자리 번호뿐이다.

**추천 방식**
1. **누가 어떤 아이템을 받았는지는 서버 표에 저장** (받은 사람, 아이템, 준 날, 이유). 휴대폰이 마음대로 "나 이 모자 있어"라고 할 수 없게, 서버 기록이 진짜다.
2. **지금 쓰고 있는 아이템**은 위치 메시지에 짧은 글자 몇 개(예: 모자 2번·안경 1번)만 덧붙인다. 새 메시지가 생기지 않는다 — 원래 보내던 메시지에 몇 글자가 붙을 뿐.
3. 다른 사람 화면은 순위표를 받을 때(이미 하고 있음) "누가 어떤 아이템을 가졌는지" 목록을 같이 받아, **받은 적 있는 아이템만** 그려 준다 (휴대폰을 고쳐서 안 받은 아이템을 써도 남에게는 안 보임).
4. 아이템을 바꿔 쓸 때만 위치 정보를 한 번 다시 보낸다 (지금 한도 30초 4번 안에서).
5. 선물을 받는 순간 "○○님이 🎩 모자를 받았어요" 알림을 한 번 보낼 수 있다 (지금 체크 축하 알림과 같은 방식, 선물 1번에 메시지 1개).

**늘어나는 양 (Supabase 무료 요금 안인지)**
- 실시간 메시지: 새로 생기는 것은 "선물 알림"과 "아이템 바꿔 쓰기" 정도 — 한 달에 많아야 수백 개. 무료 한도(한 달 실시간 메시지 약 200만 개, 동시 접속 200명)에 비하면 아주 작다.
- 메시지 크기: 한 번에 10글자 안팎 더해질 뿐.
- 서버 저장: 받은 아이템 한 줄 = 아주 작은 기록. 팀원 50명이 한 달에 3개씩 1년을 받아도 2천 줄도 안 되고, 무료 저장 공간(500MB)에 비하면 거의 0.
- → **무료 요금 안에서 충분하다.** 돈이 드는 설정은 필요 없다. (무료 한도 숫자는 만들기 전에 Supabase 요금 화면에서 한 번 더 확인)

## 4. 상 받은 사람에게 주는 방식
| 안 | 어떻게 | 좋은 점 | 아쉬운 점 |
|---|---|---|---|
| **A. 관리자가 주기 (추천, 먼저)** | 관리자 칸 "팀원 관리" 명단에서 이름 옆 "🎁 아이템 주기" → 아이템 고르기 → 이유 한 줄(예: 10월 개근상) → 주기 | 회장님·맡은 리더가 원하는 때 원하는 사람에게. 상 규칙이 정해지기 전에도 쓸 수 있음. 소감상처럼 사람이 골라야 하는 상에 맞음 | 매달 사람이 직접 눌러야 함 |
| **B. 매달 상 3개와 자동 연결** | 매달 1일, 지난달 결과로 저절로 줌: **점수왕** = 지난달 점수 1등, **개근상** = 지난달 들어온 날수(10코어 체크한 날) 가장 많은 분(같으면 모두), **소감상** = 관리자가 고름 | 손이 덜 감. 공정해 보임 | 소감상은 숫자로 못 정해서 결국 관리자가 골라야 함. 동점·빠진 날 규칙을 먼저 정해야 함 |

- **추천 순서: A를 먼저 만들고, 상 규칙이 확정되면 B를 덧붙인다.** B를 붙여도 소감상은 A(관리자 고르기)로 준다.
- 숫자 근거는 이미 있다: 11/5에 올린 "한 달 점수판"이 이번 달·지난달 점수와 날수를 서버에서 계산한다 → 점수왕·개근상은 이 계산을 그대로 쓰면 된다.
- 확인할 점: 저장소에는 지금 "꾸준상"(주간) 발표가 **회장님 상 규칙 승인 전이라 숨겨져** 있고, "소감상·개근상·점수왕" 3개 상은 아직 코드·회사 문서에 규칙이 없다. 상 이름과 규칙(동점, 기준 날짜)을 회장님께 먼저 결재받아야 B를 만들 수 있다.
- 아이템은 진짜 선물이 아니라 화면 속 꾸밈이다. 돈으로 사거나 바꿀 수 없게 만든다 (사고팔기 없음, 현금 가치 없음).

## 5. 서버 설정(SQL)
- **필요하다.** 새 표 2개(받은 아이템, 쓰고 있는 아이템)와 함수 몇 개(아이템 목록 받기, 관리자가 주기, 매달 자동 주기)를 만든다. 지금처럼 `migration-아이템.sql` 파일로 만들고, **회장님 크롬 Claude 지시문**(SQL Editor에 붙여 넣기)을 따로 쓴다.
- 지우는 문장 없이 "새로 만들기"만 하게 짠다. SQL 전에는 아이템 칸이 숨어 있게 해서, 앱과 SQL 순서가 바뀌어도 라운지가 깨지지 않게 한다 (한 달 점수판과 같은 방식).
- 자동 주기(B)는 매달 1일 서버가 저절로 돌리는 예약 기능이 필요하다. 무료 요금에서 쓸 수 있는 방법이 있지만, 더 간단하게 "1일 이후 누군가 라운지를 처음 열 때 지난달 상을 한 번 확정"하는 방식도 된다 (지난달 1등 확정과 같은 방식).

## 6. 만들면 걸리는 시간 (대략)
| 단계 | 내용 | 대략 |
|---|---|---|
| 1 | 아이템 모양 4종 × 색 2~3개 (모자·안경·가방·신발), 앉기·자전거·요가 자세 확인 | 1일 |
| 2 | "내 아이템" 창 (받은 것 보기·쓰기·벗기), 다른 사람 화면에 보이기 | 1일 |
| 3 | 서버 SQL + 관리자 "아이템 주기" + 선물 알림 + 크롬 Claude 지시문 | 1일 |
| 4 | 매달 상 3개 자동 연결 (상 규칙 결재 뒤) | 0.5~1일 |
| 5 | 시험(여러 휴대폰 동시, 옛 버전 휴대폰과 섞여도 안 깨지는지) · 품질관리팀 검수 | 0.5~1일 |
- **A(관리자 주기)까지 약 3~4일, B(자동 상)까지 약 4~5일.** (회사 작업 시간 기준, 결재·SQL 실행 기다리는 시간 빼고)

## 7. 위험한 점
1. **휴대폰 속도** — 사람이 많을 때 아이템까지 그리면 오래된 휴대폰이 느려질 수 있음 → 도형 수를 적게, 멀리 있는 사람 아이템은 간단하게.
2. **앉기 자세와 겹침** — 가방이 의자 등받이를, 신발이 바닥·매트를 뚫어 보일 수 있음 → 자리 종류별로 확인, 필요하면 앉을 때 가방 숨김.
3. **속이기** — 휴대폰을 고쳐 안 받은 아이템을 쓰는 것 → 서버 목록에 있는 것만 남에게 보이게 (3장 3번).
4. **서운함·비교** — 상 못 받은 분이 소외감을 느낄 수 있음 → 처음 들어온 분 모두에게 기본 아이템 1개(예: 기본 모자 색) 선물, 상 아이템은 "특별한 색"으로만 구분하는 방법 추천.
5. **상 규칙 미정** — 상 이름·기준이 결재 전이라, 자동 연결(B)은 결재 뒤에 만든다.
6. **옛 버전 휴대폰** — 새 버전을 안 받은 휴대폰은 다른 사람 아이템을 못 보지만 깨지지는 않게 만든다 (모르는 내용은 무시하는 방식).
7. **암웨이 규정** — 아이템에 회사·제품 이름·로고를 넣지 않고, 돈이 오가지 않는 화면 속 꾸밈으로만 둔다.

## 8. 회사 추천안 (결재용 한 줄)
"관리자가 주는 꾸밈 아이템(모자·안경·가방·신발) 먼저 만들기 — 무료 요금 안, 서버 SQL 1번(크롬 Claude), 약 3~4일. 상 3개 규칙을 정해 주시면 매달 자동으로 주는 것까지 붙이겠습니다."
