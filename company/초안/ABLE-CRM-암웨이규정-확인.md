# ABLE CRM — 고객 암웨이 비밀번호·카드 정보 보관, 대신 주문, 앱 판매 규정 확인 (암웨이사업팀 초안)

> 2026-11-02 · 암웨이사업팀 · 회장님 결재 전 초안
> 근거: 노션 비공개 "🔒 암웨이 사업실"의 **윤리강령 1~15조 요약**, **SNS·온라인 정책 요약**, 공지 No.1303608 요약
> 주의: 노션에 있는 것은 **요약**이고 조항 원문 전체가 아닙니다. 아래에서 "확인 못 함"은 요약에 없어 원문을 못 본 것입니다.
> 고객·파트너 이름, 연락처, 계정, 카드 정보는 이 파일에 적지 않았습니다.

## 한 줄 결론
**고객 암웨이 비밀번호와 카드 정보는 암호화해도 "보관 자체"가 위험합니다. 앱에서 빼고 지우는 것을 추천합니다(삭제라 회장님 결재 필요).** 고객 동의서로는 해결되지 않습니다. 이 기능이 들어간 앱을 다른 파트너에게 파는 것은 윤리강령 7조(사업 보조 자료 판매·유료화 금지)에 걸릴 가능성이 높습니다.

## 질문 1. 파트너가 고객 아이디·비밀번호로 대신 주문해도 되나? 동의가 있으면 되나?

| 구분 | 내용 |
|---|---|
| 윤리강령에 "남의 계정으로 대신 주문"을 직접 다룬 조항 | **확인 못 함** (노션 요약 1~15조에 없음) |
| 암웨이 쇼핑몰 이용약관(아이디·비밀번호를 남에게 알려 주거나 남이 쓰게 하는 것) | **확인 못 함** (노션에 없음. 보통 쇼핑몰 약관은 "본인만 사용, 제3자 이용 금지"를 둠 — 추측) |
| 관련될 수 있는 조항 (요약 기준) | **4조** 그룹 간 제품 매매·재판매·실적 조작 금지 → 파트너가 고객 계정으로 주문하면서 결제·배송·실적이 섞이면 "재판매" 또는 "실적 조작"으로 보일 수 있음 / **3조** 제품 구매 강요 금지 → 파트너가 주문 버튼을 쥐고 있으면 고객이 원치 않는 주문이 생길 수 있는 구조 / **1조** 정직하고 책임감 있게 |
| 고객 동의가 있으면 되나 | **동의만으로 된다고 볼 근거를 못 찾음.** 약관이 "본인만 사용"이면 고객이 동의해도 약관 위반은 그대로임(확인 못 함) |

**판단**: 규정 원문 확인 전까지 **"하지 않음"으로 취급**합니다. 대신 주문이 필요하면 아래 4번의 "고객이 직접 주문" 방식으로 바꿉니다.

## 질문 2. 고객 카드 정보를 파트너가 보관해도 되나?

| 구분 | 내용 |
|---|---|
| 윤리강령·SNS 정책에 카드 정보 보관 조항 | **확인 못 함** (요약에 없음) |
| 법·카드 업계 기준 (회사가 아는 일반 원칙, 이번에 조문 원문은 다시 확인 안 함) | ① 카드번호·유효기간·카드 비밀번호 일부·생년월일을 함께 가지면 **남이 카드 결제를 할 수 있는 정보 한 벌**이 됨. 이런 정보는 카드사·결제대행사처럼 허가받은 곳만 보관하는 영역이고, 개인이나 일반 앱이 모아 두는 것은 매우 위험 ② 카드를 남에게 빌려주거나 남이 쓰게 하는 것은 카드 회원 약관·관련 법(여신전문금융업법)에서 막는 행위일 가능성 ③ 개인정보 보호법: 비밀번호는 **되돌릴 수 없게(일방향) 암호화**하는 것이 원칙인데, 대신 로그인하려면 되돌려야 하므로 **구조적으로 맞지 않음** ④ 유출되면 신고·배상 책임이 앱 운영자(회장님)에게 옴 |

**판단**: **보관하면 안 되는 쪽으로 봅니다.** 암호화(금고)는 "도둑맞을 확률"을 줄일 뿐, "보관해도 되는가" 문제는 그대로입니다.
→ 회사 추천: 이미 승인된 "암호화·지우지 않음"을 **다시 결재**에 올려 **"카드 정보·암웨이 비밀번호 칸 삭제"** 로 바꾸기. (지우는 일이라 회장님 승인 필요)

## 질문 3. 이 앱을 다른 사업자(파트너)에게 파는 것 — 윤리강령 7조

| 조항 (요약 기준) | 이 앱에 대입 |
|---|---|
| **7조 사업 보조 자료(BSM)**: 책·영상·SNS·행사 등은 **사전 서면 승인** 필요, **판매나 유료화 금지**, 구매 강요 금지 | ABLE CRM은 암웨이 고객 재구매·주문을 돕는 도구라 BSM으로 볼 가능성이 큼. 그러면 **승인 없이 쓰게 하는 것도, 돈을 받는 것도 문제** |
| **SNS 정책**: 블로그·카페·웹사이트·**앱** 개설 콘셉트는 사전 서면 승인 필요 | 앱 자체가 승인 대상일 가능성 |
| **9조 상표**: 암웨이 이름·로고를 사업명에 쓰지 않음 | 앱 안에 암웨이 이름·제품명이 있으면 걸림 |
| **3조·5조** 강요 금지, 독립성 존중 | 윗라인이 팀에 "써야 한다"고 하면 강요로 보일 수 있음 |
| 다른 나라 암웨이 7장 (참고, 한국 아님) | 원가로만, 이익 금지, 사업자 아닌 사람에게 판매 금지 (`윗라인-도구요청-규정.md`) |
| "앱(소프트웨어)도 BSM에 들어가는지" 한국 원문 정의 | **확인 못 함** (2조 정의 원문, 7조 원문 필요) |

**판단**: 지금 모습(암웨이 고객용 + 암웨이 계정·카드 정보 기능) 그대로 파트너에게 팔면 **위반 가능성 높음**. 남의 고객 비밀번호·카드 정보까지 회장님 서버에 모이게 되어 위험이 몇 배로 커집니다.

## 4. 괜찮은 방법 (회사 추천 순서)

1. **대신 주문 → "고객이 직접 주문"으로 바꾸기**: 파트너는 앱에서 "주문할 제품 목록"만 만들어 고객에게 보내고, 고객이 본인 휴대폰으로 로그인·결제. 앱에는 비밀번호·카드 칸을 두지 않음.
2. **암웨이 공식 기능 확인**: 한국암웨이에 대리 주문, 장바구니 공유, 정기 배송(자동 주문), 선물·배송지 지정 같은 공식 기능이 있는지 → **확인 못 함**. 회장님이 사업자 사이트·앱에서 메뉴 화면을 캡처해 노션 "자료 올리는 곳"에 올려 주시면 회사가 정리합니다.
3. **파는 앱은 따로**: 판매용은 암웨이 이름·제품·계정·카드 기능을 뺀 "1인 판매자 일반용"으로 (결재 16번 추천과 같음). 암웨이 팀용은 판매하지 않고, 쓰더라도 사전 승인 여부부터 확인.
4. **고객 동의서 문구** (카드·비밀번호가 **아닌** 일반 정보용. 동의서로 카드·비밀번호 보관이 괜찮아지지는 않습니다)

```
[고객 정보 저장 동의 — 초안, 규정·법 확인 전]
저는 담당 파트너가 아래 정보를 고객 관리(재구매 시기 안내, 상담 기록) 목적으로만
저장하는 것에 동의합니다.
- 저장하는 것: 이름(또는 별칭), 연락처, 구매한 제품과 날짜, 상담 메모
- 저장하지 않는 것: 암웨이 아이디·비밀번호, 카드 정보, 주민등록번호
- 보관 기간: 동의를 거두실 때까지 (거두시면 바로 지웁니다)
- 다른 사람에게 주지 않습니다.
- 안내 메시지는 받지 않겠다고 하시면 바로 멈춥니다.
- 동의하지 않으셔도 제품 구매에 불이익은 없습니다.
날짜 / 이름 / 서명
```
※ 이 문구는 앱출시팀(약관·처리방침 담당)과 품질관리팀 검수, 개인정보 전문가 확인 후 씁니다. 광고 메시지 동의는 2년마다 다시 확인, 밤 9시~아침 8시는 별도 동의(SNS 정책 요약).
