# ARTPLAY 블로그 글 도구 — 화면 설계 (디자인팀 초안)

- 고객: ARTPLAY 인테리어 (네이버 블로그 "ARTPLAY | 공간을 디자인하다")
- 사용자: ARTPLAY 사장님, 아이폰, 현장에서 한 손으로
- 만드는 곳: claude.ai 페이지(아티팩트) 1개
- 하는 일 한 가지: **시공 사진 + 한 줄 메모 → 네이버 블로그 글 초안(제목·본문·해시태그) → 복사**
- 작성: 디자인팀, 2026-11-01 / 상태: 초안 (검수 전)

---

## 1. 화면 흐름 (한 화면, 위에서 아래로 내려가며)

화면은 한 장입니다. 페이지를 넘기지 않고, 위에서 아래로 차례대로 채우면 맨 아래에 [글 만들기]가 있습니다. 글이 만들어지면 같은 화면 아래에 결과가 나오고 화면이 결과 위치로 자동으로 내려갑니다.

```
┌────────────────────────────┐
│  ART. PLAY        [지난 글] │  ← 머리 (높이 56px, 위에 붙어 있음)
│  블로그 글 만들기            │
├────────────────────────────┤
│ ① 사진 넣기                 │
│  ⚠ 고객 집 주소·얼굴·차량    │
│    번호가 보이는 사진은      │
│    빼 주세요.               │
│  [ 전 ]  ┌──┐┌──┐┌ + ┐      │
│  [ 후 ]  ┌──┐┌──┐┌──┐┌ + ┐  │
├────────────────────────────┤
│ ② 고르기                    │
│  공간  (주방)(거실)(욕실)…   │
│  공사  (전체 리모델링)(부분)… │
│  평수  (10평 이하)(20평대)…  │
│  글 종류 (시공 후기)(전후 비교)(팁) │
├────────────────────────────┤
│ ③ 한 줄 메모                │
│  [ 예: 30년 된 주방, 상부장  ] │
│  [ 없애고 화이트 타일로     ] │
├────────────────────────────┤
│ [        글 만들기        ] │  ← 큰 버튼 (높이 56px)
├────────────────────────────┤
│ ⑤ 결과                      │
│  제목 고르기 (3개 중 하나)   │
│  📷 사진 넣는 순서          │
│  본문                       │
│  해시태그                   │
│  [전체 복사]                 │
│  [제목만][본문만][해시태그]   │
│  [다시 만들기]               │
└────────────────────────────┘
```

### 머리 (맨 위, 위에 붙어 있음)
| 무엇 | 크기·위치 | 설명 |
|---|---|---|
| 로고 "ART. PLAY" | 왼쪽, 손글씨 글꼴 28px | 블로그 첫 화면과 같은 느낌. 글자로 넣는다(그림 파일 아님) |
| 작은 글 "블로그 글 만들기" | 로고 아래, 14px, 흐린 색 | 무슨 도구인지 한 줄로 |
| [지난 글] 버튼 | 오른쪽, 44×44px 이상 | 4번 항목 참고 |

### ① 사진 넣기
- 제목 "① 사진 넣기" (20px, 굵게)
- **개인정보 주의 문구는 사진 칸 바로 위, 항상 보이게** (5번 항목 참고).
- 줄 2개: **[전]** 줄, **[후]** 줄. 줄 머리에 "전" "후" 이름표(16px, 굵게).
- 각 줄에 사진 칸이 가로로 나란히. 칸 크기 **88×88px**, 칸 사이 8px. 넘치면 옆으로 밀어서 봄.
- 마지막 칸은 **[+] 칸**(88×88px, 점선 테두리). 누르면 아이폰 사진 고르기 창이 열림(여러 장 한 번에 고르기 가능).
- 넣은 사진 칸 오른쪽 위에 **[×] 빼기**(누르는 영역 44×44px, 보이는 동그라미는 24px).
- 사진 칸 아래에 작은 번호 "사진 1", "사진 2"… — 전 사진부터, 그다음 후 사진 순서로 번호가 이어진다. 이 번호가 결과의 "사진 넣는 순서"와 같다.
- 한도: 전 6장 + 후 6장 = 최대 12장. 넘으면 "사진은 전·후 각각 6장까지 넣을 수 있어요." 한 줄.
- 사진 없이도 글은 만들 수 있다(메모와 버튼만으로). 이때 [글 만들기] 위에 흐린 글씨 "사진이 없으면 사진 순서 안내는 빠져요."
- "전/후 비교" 글 종류를 골랐는데 전 사진이 0장이면: "전 사진을 1장 이상 넣어 주세요." (버튼은 막지 않고 안내만)

### ② 버튼으로 고르기
버튼 모양: 둥근 알약 모양(높이 44px, 좌우 여백 16px, 글자 16px). 고르면 바탕이 검정(밤 모드는 흰색)으로 채워지고 앞에 ✓ 표시. 줄이 넘치면 다음 줄로 내려감(옆으로 밀지 않음 — 한눈에 다 보이게).

| 묶음 | 버튼 | 고르는 방식 |
|---|---|---|
| 공간 | 주방 · 거실 · 욕실 · 침실 · 현관 · 상가 · 기타 | **여러 개 가능** (주방+거실 같이 한 공사 많음) |
| 공사 | 전체 리모델링 · 부분 · 가구 · 조명 · 도배 · DIY | **여러 개 가능** |
| 평수 | 10평 이하 · 10평대 · 20평대 · 30평대 · 40평 이상 · 모름 | **하나만** |
| 글 종류 | 시공 후기 · 전후 비교 · 팁 | **하나만**, 처음엔 "시공 후기"가 골라져 있음 |

- "기타"를 고르면 그 아래에 짧은 입력 칸이 하나 열림(예: "사무실", "카페").
- 평수는 숫자 입력 대신 버튼으로(아이폰 숫자판 열고 닫는 수고를 없앰). "모름"을 고르면 글에 평수를 쓰지 않는다.
- 필수: 공간 1개 이상. 나머지는 안 골라도 글이 만들어진다.

### ③ 메모 한 줄
- 입력 칸 1개, 높이 2줄(최소 72px), 글자 16px(16px 미만이면 아이폰이 화면을 확대해 버림).
- 안내 글(칸 안 흐린 글씨): "예: 30년 된 주방, 상부장 없애고 화이트 타일로 밝게"
- 아래 작은 글씨: "현장에서 기억나는 것 한 줄이면 충분해요."
- 최대 200자. 남은 글자 수는 쓰지 않는다(화면 복잡함 방지).

### ④ [글 만들기]
- 화면 너비 꽉 채운 큰 버튼, **높이 56px**, 글자 18px 굵게, 검정 바탕 흰 글씨.
- 공간을 안 골랐으면 눌렀을 때 공간 묶음으로 화면이 올라가고 "공간을 하나 골라 주세요."를 빨간 글씨 대신 진한 회색 테두리 + 굵은 글씨로 보여 줌(무채색 유지).
- 누르면 버튼 글자가 "글 쓰는 중… (20초쯤)"으로 바뀌고 버튼은 잠깐 눌리지 않음.
- 실패하면: "글을 못 만들었어요. [다시 시도]" — 버튼 하나만.

### ⑤ 결과
같은 화면 아래에 나오고, 화면이 결과 맨 위로 부드럽게 내려간다.

**제목 고르기**
- 제목 후보 3개를 카드 3장으로 세로로. 카드 높이 최소 56px, 글자 17px.
- 처음엔 1번이 골라져 있음(테두리 두껍게 + 왼쪽 ●). 다른 카드를 누르면 그 제목으로 바뀜.
- 골라진 제목이 [전체 복사]·[제목만 복사]에 쓰인다.

**📷 사진 넣는 순서** (사진을 넣었을 때만)
- 네이버 블로그 앱에서 사진을 어떤 순서로 올리면 되는지 짧은 목록.
- 예:
  ```
  📷 사진 넣는 순서
  사진 1 — 전: 공사 전 주방 전체
  사진 2 — 전: 낡은 상부장
  사진 3 — 후: 화이트 타일 주방 전체
  사진 4 — 후: 새 조명 가까이
  ```
- 본문 안에도 사진 자리를 `[📷 사진 1]` 처럼 표시해 둔다 → 사장님이 블로그 앱에서 그 자리에 사진을 넣으면 됨.
- 사진 설명(“공사 전 주방 전체” 같은 말)은 AI가 사진을 볼 수 있을 때만 구체적으로. 못 보면 "전 사진 1", "후 사진 1"처럼 순서만(6번 항목 참고).

**본문**
- 회색 종이 카드 안에 그대로 보여 줌. 글자 16px, 줄 간격 1.7.
- 네이버 블로그에 붙여 넣기 좋게: 짧은 문단, 문단 사이 빈 줄, 소제목은 【 】로 감싸기(네이버 앱은 붙여 넣으면 굵게 등 꾸밈이 빠지므로 기호로 구분).
- 본문은 결과 화면에서 바로 고칠 수 있게 입력 칸으로 둔다(한두 단어 고치려고 다시 만들지 않도록).

**해시태그**
- 10~15개, 한 줄씩 이어서 `#주방리모델링 #ARTPLAY인테리어 …`
- 고정 태그 2개는 항상 포함: `#ARTPLAY` `#아트플레이인테리어` (사장님 확인 필요 — 8번 항목)

**복사 버튼**
| 버튼 | 크기 | 복사되는 것 |
|---|---|---|
| **[전체 복사]** | 너비 꽉 채움, 높이 56px, 검정 | 고른 제목 + 빈 줄 + 본문 + 빈 줄 + 해시태그 |
| [제목만 복사] | 3칸 나란히, 높이 48px, 흰 바탕 검정 테두리 | 고른 제목 |
| [본문만 복사] | 〃 | 본문 (사진 자리 표시 포함) |
| [해시태그 복사] | 〃 | 해시태그 한 줄 |

- 누르면 버튼 글자가 1.5초 동안 "✓ 복사됨"으로 바뀜. 따로 알림 창은 띄우지 않음.
- 아이폰 화면 폭(375px)에서 3칸은 칸당 약 110px → 글자 16px로 "제목만 복사" 5글자가 들어감. 좁으면 "제목만"·"본문만"·"해시태그"로 줄여도 됨.
- 복사 아래 작은 안내: "네이버 블로그 앱 → 글쓰기 → 길게 눌러 붙여넣기"

**[다시 만들기]**
- 복사 버튼 아래, 흰 바탕 테두리 버튼, 높이 48px.
- 같은 사진·버튼·메모로 새 글을 다시 만든다. 지금 글은 지난 글 목록에 남는다.

## 2. 색·글꼴 (ARTPLAY 느낌)

블로그 첫 화면처럼 **회색 석고·종이 질감 + 검은 손글씨 + 차분한 무채색**. 색은 무채색만 쓰고, 강조는 "검정의 진하기"로만 한다.

### 색 (회사 앱 `style.css`와 같은 이름 체계)
| 이름 | 낮 모드 | 밤 모드 | 쓰는 곳 |
|---|---|---|---|
| `--bg` | `#e9e7e3` (석고 회색) | `#1c1c1b` (젖은 콘크리트) | 화면 바탕 + 종이 질감 |
| `--card` | `#f6f5f2` (종이) | `#262625` | 묶음 카드, 결과 카드 |
| `--text` | `#1a1a1a` (먹색) | `#ecebe8` | 글자 |
| `--muted` | `#6e6c68` | `#a3a19c` | 작은 안내 글 |
| `--line` | `#d3d0ca` | `#3a3937` | 테두리 |
| `--btn` | `#1a1a1a` | `#ecebe8` | 주 버튼 바탕, 골라진 버튼 |
| `--btn-text` | `#ffffff` | `#1a1a1a` | 주 버튼 글자 |
| `--note` | `#dedbd5` | `#2f2e2c` | 개인정보 주의 상자 바탕 |

- 글자/바탕 대비는 `--text` 대 `--bg` 기준 약 14:1, `--muted` 대 `--card` 약 5:1 이상(읽기 기준 4.5:1 넘음).
- 모서리 둥글기: 회사 앱(18px)보다 덜 둥글게 **12px** — 석고·건축 느낌을 위해. 그림자는 아주 약하게(`0 1px 2px rgba(0,0,0,.05)`).
- **종이 질감**: 그림 파일 없이 CSS 안의 작은 SVG 노이즈(feTurbulence)를 바탕에 3~4% 투명도로 깐다. 밤 모드에서는 2%. (그림 파일을 따로 두지 않으므로 claude.ai 페이지 한 장에 다 들어감)
- 밤 모드: 아이폰 설정을 따라 자동 전환(`prefers-color-scheme`). 따로 전환 버튼은 두지 않는다.

### 글꼴 (Google Fonts)
| 쓰는 곳 | 글꼴 | 크기 |
|---|---|---|
| 로고 "ART. PLAY" (영문) | **Caveat Brush** | 28px |
| 묶음 제목 ①②③ (한글 손글씨) | **Nanum Pen Script** | 26px (이 글꼴은 작아 보여서 크게) |
| 본문·버튼·결과 글 | **IBM Plex Sans KR** (회사 앱과 같음) | 16px 이상, 결과 제목 17px, 큰 버튼 18px |
| 대체 글꼴 | `-apple-system, "Apple SD Gothic Neo", "Noto Sans KR", sans-serif` | |

- 손글씨는 로고와 묶음 제목에만. 버튼·본문·결과에는 절대 쓰지 않는다(읽기 어려움).
- 결과 본문은 네이버에 붙여 넣으면 네이버 글꼴로 바뀌므로, 화면에서는 읽기 쉬운 것만 신경 쓴다.

## 3. 휴대폰 한 손 사용

- 누르는 곳은 모두 **44px 이상**. 큰 버튼([글 만들기], [전체 복사])은 56px.
- 글자는 모두 **16px 이상**. 예외는 사진 번호·작은 안내(14px)뿐이고, 이것들은 눌리는 곳이 아니다.
- 버튼 사이 간격 8px 이상(잘못 누름 방지).
- 화면 좌우 여백 16px, 최대 너비 480px(아이패드에서도 가운데 한 줄로).
- 아이폰 아래쪽 홈 막대 공간 확보(`env(safe-area-inset-bottom)`).
- 엄지가 닿는 아래쪽에 주 버튼이 오도록: [글 만들기]는 입력 맨 아래, [전체 복사]는 결과에서 제목 바로 아래가 아니라 해시태그 아래(다 읽고 누르는 자리).

## 4. 지난 글 목록·다시 만들기 — 판단

**결론: 둘 다 넣는다. 단, 지난 글은 버튼 하나 뒤에 숨겨서 첫 화면을 복잡하게 하지 않는다.**

- **[다시 만들기] — 넣음.** AI 글은 한 번에 마음에 안 들 때가 많다. 사진·버튼·메모를 다시 넣게 하면 사장님이 안 쓰게 됨.
- **지난 글 목록 — 넣음 (최근 10개, 이 기기에만 저장).** 현장에서 만들고 저녁에 블로그에 올리는 일이 흔할 것. 복사하다 실수로 화면을 닫아도 되찾을 수 있어야 한다.
  - 머리 오른쪽 [지난 글] 버튼 → 아래에서 올라오는 목록 판.
  - 한 줄에: 날짜(11월 1일) · 고른 제목 · 공간(주방). 줄 높이 56px.
  - 누르면 그 결과 화면이 그대로 열림(복사 버튼 4개 포함).
  - 11번째가 생기면 가장 오래된 것이 자동으로 빠짐. 각 줄 왼쪽으로 밀면 [지우기].
  - **사진은 저장하지 않는다** — 글(제목·본문·해시태그)과 고른 버튼, 메모만. 이유: 저장 공간이 작고, 고객 집 사진이 기기에 남는 것을 줄이기 위해.
  - 목록 판 맨 아래 작은 글씨: "이 휴대폰에만 저장돼요. 다른 기기에서는 안 보여요."

## 6. 개발팀이 확인할 점

1. **사진을 AI가 볼 수 있는가.** claude.ai 페이지 안에서 부르는 AI(`window.claude.complete`)가 사진(이미지)을 받아 내용을 읽을 수 있는지 확인. 
   - 된다 → 사진마다 "무엇이 보이는지"를 짧게 설명받아 ① 본문에 반영(“화이트 타일과 우드 상판이 어우러져…”) ② 사진 넣는 순서 설명 ③ 5번의 개인정보 경고에 쓴다.
   - 안 된다 → 사진은 **개수와 전/후 순서만** 글에 쓴다("[📷 사진 1] 공사 전 모습"). 화면 설계는 그대로 두고 사진 설명만 순서 번호로 바뀐다. 이 경우 사진 칸 아래에 "사진 내용은 글에 들어가지 않고, 순서만 안내돼요." 한 줄을 넣는다.
2. **사진 크기.** 아이폰 사진은 장당 3~5MB. AI에 보낸다면 보내기 전에 기기 안에서 긴 변 1024px 정도로 줄여야 할 것(12장 한 번에 보내도 되는지, 한 장씩 나눠 보내야 하는지 확인).
3. **사진 형식.** 아이폰 기본 HEIC 사진이 페이지에서 미리보기·변환되는지.
4. **이 기기 저장.** claude.ai 페이지에서 지난 글 저장(브라우저 저장소)이 되는지. 안 되면 지난 글 목록은 빼고 [다시 만들기]만 남긴다(화면에서 [지난 글] 버튼만 사라지면 됨).
5. **복사.** 아이폰 사파리·claude 앱 안에서 복사 버튼이 실제로 되는지(꼭 회장님 아이폰에서 확인). 안 되면 결과 글을 길게 눌러 복사하도록 안내 문구로 대신.
6. **사진 보관하지 않기.** 사진은 글 만들 때만 쓰고 저장하지 않는다(4번 항목).
